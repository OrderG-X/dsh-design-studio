# 界面设计（配合右侧「设计工作台」）

做网页、App 界面、平板界面、海报 / 社媒图、幻灯片、邮件、组件这类**看得见的设计**时照这份来。目标：一眼看上去像专业设计师做的，不像模板，也没有「AI 味」。

## 流程

0. **新做一套设计：先问清，先出方向**。

   - **什么时候跳过**：改已有的设计；用户说了「直接做」「不用问」；或者需求已经够具体（做什么、给谁用、什么风格或配色、要哪几屏都说了）。这时不问、也不出三个方向，第一句话说清你按什么理解开工（「按温暖手作风格做首页、详情、购物车三屏」），直接从第 1 步做全套。拿不准算不算够具体，就只问缺的那一两项。

   - **问**：只问最关键的两三个问题，一次问完：给谁用、想要什么感觉（给三个具体选项，从工作台的风格卡里挑最合场景的三个：极简白、温暖手作、杂志编辑、深色高级、活泼年轻、清新自然、专业科技、玻璃质感、柔和立体）、有没有必须有的内容或品牌色。有 `ask_user_question` 工具就用它问（带选项），没有就在回复里问完、停下等回答。用户说「你定」就按场景替他定。
   - **用户点了风格卡**（消息以〔风格〕开头，带着配色、字体、形状和要点）：感觉已经定了，不用再问感觉，只问还缺的（给谁用、必须有的内容）；三个方向都按这套配色和字体来，在版式和信息重点上拉开。
   - **出三个方向**：先只做最能代表这套设计的一屏（通常是首页或封面），做三个明显不同的方向：`home-a.html`、`home-b.html`、`home-c.html`。用户已经挑了感觉（比如「温暖手作」），三个方向就都在这个感觉里拉开：版式、信息重点、字体搭配、配色深浅各不相同（比如「大图海报式 / 卡片列表式 / 一步下单式」），不要再出两个他没选的风格；没挑或说「你定」，三个方向就是三种不同的感觉。不管哪种，都不是同一个版式换颜色。这时还不建 `tokens.css`，每个方向的设计变量写在自己文件的 `<style>` 里（`:root{…}`）。`<title>` 写成「方向 A · 温暖手作」这样，画布上一眼分得清。写完第一个就调 `preview_page`，另外两个会并排出现。
   - **等用户挑**：一两句话说清三个方向各自的特点，问用户要哪个（也可以混搭：「A 的配色 + C 的版式」）。用户也可能直接在画布上点「就要这个」，消息以〔选定方向〕开头，照里面说的收尾。挑定以后：把选中方向的变量搬进 `tokens.css`，那个文件改成正式的名字（`home.html`）并改用 `tokens.css`，另外两个移进 `drafts/` 子目录（别删），然后按下面的流程做全套。

1. **先定类型和画幅**（拿不准就按用户说的场景选）：

   | kind | 画幅 | 外框 | 细则 |
   | --- | --- | --- | --- |
   | `web` | 1280×800 起，自适应 | 浏览器窗口 | `references/web.md` |
   | `app` | 390×844（iPhone） | 手机 + 灵动岛 | `references/app.md` |
   | `tablet` | 820×1180 | 平板 | `references/app.md` 末尾 |
   | `poster` | 1080×1350（4:5），可改 1080×1920 / 1080×1080 | 卡片 | `references/poster.md` |
   | `slides` | 1280×720（16:9） | 卡片 | `references/slides.md` |
   | `email` | 600 宽 | 卡片 | `references/email.md` |

   细则只在做那一类时再读。

2. **先写设计变量**：在设计目录建 `tokens.css`（起手模板 `tokens.css` 就在这个技能目录里，复制过去再按品牌改），颜色、字体、字号阶梯、间距、圆角、阴影都从这里取。每屏都 `<link rel="stylesheet" href="tokens.css">`。之后要统一改风格，改这一个文件，所有屏一起变。

3. **一屏一个 HTML 文件，放同一个目录**，按用户会看的顺序一屏一屏写（画布按创建顺序排：登录 → 首页 → 详情 → …）。文件名用英文小写（`login.html`、`home.html`），`<title>` 写这屏的中文名（画布上显示它）。临时试验的页面用 `_` 开头（`_test.html`），不会上画布。每屏 `<head>` 里写：

   ```html
   <meta name="dsh-design" content="app">          <!-- 类型；海报可带尺寸：poster 1080x1920 -->
   ```

   **几屏共用的东西只写一份**：样式放 `tokens.css` 和一个公共的 `app.css`；图标、书封这类 SVG 放进一个 `icons.svg`（每个图标一个 `<symbol id="…">`），页面里用 `<svg><use href="icons.svg#cart"></use></svg>` 引用——换风格时改一处所有屏一起变，不会漏改。状态栏、标签栏这种 HTML 结构每屏照抄一份，保持一模一样。

   **几屏之间用真链接串起来**，让它成为点得动的原型：按钮、卡片、标签栏、返回箭头都写成 `<a href="detail.html">`（或 `data-href="detail.html"`）。返回也写具体去哪一屏（`<a href="home.html">`），不要用 `history.back()`。右侧画布会从按钮画一条连线到目标屏，「演示」时点按钮就跳过去（带过场动画），手机扫码看时也点得动。

4. **写完第一屏就调 `preview_page`**（`target` 填这个文件，`kind` 填类型），用户从第一屏起就能看着它长出来；后面的屏写到同一目录会自动并排出现，不用再调。

5. **写完先量、再看，然后收尾**：
   - **量**：调 `check_design`。它在电脑上用无头浏览器按真实尺寸打开每一屏实测（文字截断、重叠、对比度、点击区、字号、变形、行太长、固定栏压住内容、脚本报错、文件没载出来、跳到不存在的页面……），返回量了哪几屏、每种尺寸下页面多高、顶栏 / 底栏离内容多远，和问题清单（哪一屏、哪个元素、具体数字）。App 顺手量一下小屏和大屏：`sizes: ["375x667", "430x932"]`；网页量手机宽：`sizes: ["390", "1280"]`。
   - **看**：调 `look_design` 看一眼真实渲染的截图，检查量不出来的东西（层次、留白、配色、图片、整体观感）；底栏多的 App 用 `at: "bottom"` 看滚到底的样子，长页面用 `at: "full"`，只看某一块用 `selector`。
   - **改**：照第 7 步的办法改，改完只重量改过的屏（`screens` 只填那几屏）。
   - **什么时候算做完**：`check_design` 没有问题（或剩下的你判断不该改，说得出理由），每屏都看过一眼截图。量 / 看 / 改最多三轮：三轮后还有的，照实列给用户，别一直磨。不要自己另写检查页、起服务、开浏览器截图——上面两个工具就是干这个的，又快又准。
   - 最后用一两句话告诉用户做了哪几屏、风格要点、还剩什么没解决。

6. **用户点选后让你改**（消息里有〔选中元素〕/〔选中区域〕）：按里面的文件和 CSS 路径找到源码改那一处；如果是颜色、字号、圆角这类风格问题，优先改 `tokens.css` 里的变量，让所有屏保持一致。

   **用户在工作台里手调过样式**：元素上的 `style="…"` 多半是用户用「调样式」拖出来的，值是用户要的，别随手删、也别改回去；整理代码时可以挪进对应的样式规则（值不变）。消息以〔调样式〕开头时，按里面的元素、选择器和「原来 → 现在」写进样式表，值是 `var(--x)` 的就用那个变量；同类元素（比如所有主按钮）该一起改就一起改，改完说一句。

   **换风格**（〔风格〕后面说「把现在的设计换成这个风格」）：先改 `tokens.css`（配色、字体、圆角、阴影按消息里的来），页面里写死的颜色换成变量，再按「要点」调细节；布局和文案不动。改完调 `check_design` 量一遍（换了配色最容易出对比度问题）。

7. **改体检出来的问题**（`check_design` 的结果，或用户发来的〔设计体检〕）：右侧工作台在渲染好的页面上实测出来的，按里面的文件、选择器和数字逐条改，没列出来的地方别动：
   - 对比度不够：调深文字色（或调浅底色），能改 `tokens.css` 里的 `muted`、主色上的文字色就改变量；
   - 文字被截断 / 超出框：放宽容器、允许换行或去掉写死的高度，别靠缩小字号硬塞；
   - 文字叠在一起：检查绝对定位和负边距，让它们回到正常排版；
   - 点击区太小：加内边距或 `min-height` / `min-width`，图标按钮的点击区可以比图标本身大；
   - 超出屏幕：找写死的宽度（`width: 600px`、`100vw` 加内边距），改成 `max-width: 100%` 或自适应；
   - 字太小、字号太杂：收到字号阶梯里的几档；
   - 图片被拉变形：加 `object-fit: cover`（要完整显示就 `contain`），或按原图比例改宽高；
   - 一行太长：给正文容器加 `max-width`（中文约 `36em`，英文约 `65ch`），别靠缩小字号。
   - 文字被挤断行：按钮、价格、标签这种短字给足宽度，或加 `white-space: nowrap`（在 flex 里再加 `flex-shrink: 0`）；一句短话最后一行只剩一两个字，就调宽度或改字。
   - 被固定栏压住 / 离固定栏太近：给内容留出栏的高度——底栏是 `position: fixed` 的，给 `body` 或内容容器加 `padding-bottom: calc(栏高 + 16px)`（App 再加 `env(safe-area-inset-bottom)`）；内容在能滚的 `main` 里，就给 `main` 加 `padding-bottom`。顶栏同理用 `padding-top`。
   - 页面脚本报错：按报的文件和行号修；纯展示用的设计稿能不写脚本就不写。
   - 文件没载出来：路径写错了（大小写、相对路径），或者文件还没建，补上或改对。
   - 跳到的页面不存在：补上那一屏，或者把链接改成已有的屏。

   改完说一句改了哪几处。这一轮结束后右侧栏会自己再量一遍，按钮上的数字没了就是都改好了。

## 设计原则

**层级**：每屏只有一个视觉焦点（最大的字 / 最亮的按钮）。用字号、字重、颜色深浅三档拉开层级，不要靠边框和分割线堆结构。主操作一个，次操作弱化成描边或文字按钮。

**间距**：全部用 4 / 8 的倍数（4、8、12、16、24、32、48、64）。相关的东西靠近、不相关的分开（亲密性）：组内间距 < 组间间距 < 区块间距。宁可留白多，不要塞满。

**字号阶梯**：比例 1.2–1.25，例如 12 / 14 / 16 / 20 / 24 / 32 / 40 / 56。一屏最多用 4 个字号。正文 15–16px，行高 1.5–1.7；标题行高 1.1–1.3，大标题字距略收（-0.02em）。一行 45–75 个字符（中文 20–35 个字）。

**颜色**：按角色定义，不按色相：背景 bg、表面 surface、文字 text、次要文字 muted、边框 line、主色 primary、强调 accent、成功 / 警告 / 危险。主色只用在关键操作和少量点缀（60 中性 – 30 辅助 – 10 主色）。中性色带一点主色的色相（暖品牌配暖灰），不要纯灰。新项目用 `oklch()` 定色，明暗一致好调。

**对比度**：正文对背景至少 4.5:1，大字（≥24px 或 ≥19px 粗体）和图标至少 3:1。浅灰字配白底最容易不合格，`muted` 别浅过 `#6b7280` 这一档。

**形状和层次**：圆角一套（如 8 / 12 / 16 / 999），同类元素圆角一致，嵌套时内圆角 = 外圆角 − 内边距。阴影最多两三档，用低透明度、大模糊、略带主色调的阴影；深色背景用亮一点的表面色区分层级，不靠阴影。

**真实内容**：不要 Lorem ipsum、「标题一」「示例文字」。写像真产品的中文文案、合理的数字和价格、真实感的人名地名。图片位置用 SVG 插画、几何构图或带色块的占位，不引用外网图片（预览离线也要好看）。

**图标**：用一套线性 SVG 图标（同样的线宽 1.75–2、圆角端点、24 网格），内联写进 HTML。不要用 emoji 当图标。

**状态**：按钮的悬停 / 按下 / 禁用，输入框的聚焦 / 出错，列表的空状态、加载、出错——用户会点的地方都要有。

**动效**：克制。150–250ms，`cubic-bezier(.2,.8,.2,1)`；只动 `transform` 和 `opacity`；加 `@media (prefers-reduced-motion: reduce)` 关掉。

**可访问性**：语义标签（`header` `nav` `main` `button`），图片有 `alt`，焦点样式看得见（`:focus-visible`），可点的区域至少 44×44。

## 中文排版

- 字体栈：`"PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", system-ui, sans-serif`；数字和英文想更精致可以把 `"Inter"` / `-apple-system` 放在前面。
- 中文不用斜体；字重用 400 / 500 / 600，标题最多 700。
- 中文和英文、数字之间加空格（「iPhone 16 发布」）；标点用全角。
- 中文行高比英文大一点（正文 1.6–1.75）；段落之间用间距分开，不用首行缩进。
- 标题不要一行只剩一两个字：调整宽度或用 `text-wrap: balance`。

## 别有「AI 味」

一眼像 AI 生成的通病，避开：

- 默认的紫蓝渐变、霓虹发光、到处玻璃拟态（毛玻璃）；
- 每个区块都居中、每段都是「图标 + 标题 + 一句话」的三栏卡片；
- 用 emoji 当图标、随手的装饰圆斑和波浪；
- 每张卡片都有大阴影和描边；一屏五六种颜色；
- 没有内容的口号式文案（「赋能」「一站式」「极致体验」）。

要做的：先想清楚品牌性格（专业 / 温暖 / 活泼 / 高端），据此选**一个**主色 + 中性色 + 一款有性格的标题字体或字重对比；排版要有节奏（大字和小字、密和疏的对比）；至少一个记忆点（一个大胆的配色、一张有特色的插画、一个不寻常的版式）。

## 自查（每次写完都过一遍）

- [ ] 所有颜色、字号、圆角都来自 `tokens.css`，没有散落的魔法数字
- [ ] 一屏只有一个焦点；主按钮只有一个
- [ ] 间距都是 4 / 8 的倍数，同类元素间距一致，左边缘对齐
- [ ] 正文对比度 ≥ 4.5:1，灰字没有太浅
- [ ] 文案是真实的中文内容，没有占位文字、没有错别字
- [ ] 图标同一套风格，没有 emoji 图标
- [ ] 画幅对：App 留出顶部 54px 状态栏和底部 34px 横条；海报 / 幻灯片内容在安全区内不溢出
- [ ] 文字没有被截断、没有伸出框、没有叠在一起；页面没有比屏幕宽；滚到底最后的内容没被底栏压住（`check_design` 实测这几项）
- [ ] 多屏之间导航、按钮、卡片样式一致（像同一个产品）
- [ ] 没有上面「AI 味」清单里的东西
