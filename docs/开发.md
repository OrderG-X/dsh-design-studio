# 设计工作台：开发和测试

## 本地开发

开发时可以直接链到本地目录：在「添加插件」里填本仓库的绝对路径，装上的是 `link:`，改了客户端代码同样要重启（`lib/picker.js` 每次现给，不用重启）。

## 架构

```
服务端  preview_page 工具 / 自动发现（session/event：写 HTML、命令输出里的地址）
          → tracker（每个会话预览什么、模型在不在干活，存 ~/.dsh/cache）
          → hub（每个目标一个本机端口：静态文件 + 改动推送 / 代理 + WebSocket 透传）
        /dsh-design-studio/api/state|open|view|close   右侧栏轮询、地址栏、类型 / 视图 / 换屏
        /dsh-design-studio/api/history|restore         版本列表、回到某一版
        /dsh-design-studio/api/export|reveal           存导出的图片、在文件夹里显示
        /dsh-design-studio/api/phone                   手机上看：开 / 关局域网入口、给二维码、电脑换屏手机跟着跳
        /dsh-design-studio/api/edit|ref                预览里改的字写回 HTML、存参考图
        /dsh-design-studio/api/style|locate            调样式：写进元素在源码里的 style 属性；按规则找回源文件和行号
        /dsh-design-studio/api/bundle                  远程看：一屏连同样式、图片打成一份（放进沙盒 iframe）
        /dsh-design-studio/api/tweak                   调节滑块写回文件（tokens.css 默认值、每屏 <html> 属性、tweaks.json）
        /dsh-design-studio/api/systems|systhumb        品牌设计系统库：列出来、设 / 取消默认、样张缩略图
        /dsh-design-studio/api/project                 转成代码前：会话目录是不是前端项目、建议放哪
        check_design / look_design → 无头浏览器（browser.js）按真实尺寸开页面，picker 里量、截图（look.js）
        extract_design_system → system.js；handoff_design / compare_design → handoff.js
页面    picker.js 注入到 HTML：悬停框选、点选 / 拖选、屏间链接、演示时接住跳转、就地改字、postMessage 回右侧栏、改动后刷新
客户端  右侧栏标签页（sidebarRightTabs）+ 标题栏按钮（session.header.utilities）
```

- `lib/index.js` —— 服务端：工具和技能的定义、接口、自动发现接线
- `lib/tool.js`、`lib/skill.js`、`lib/auto.js`、`lib/preset.js` —— 能单独开关的几个组件：挂工具、挂技能、自动打开预览、设计模式（`cordis.patch.yml` 里列着；设计模式照抄 DSH 标准模式的插件，再挂上工具和技能）
- `lib/core.js` —— 地址解析、自动发现、会话状态和存盘、每轮前后存版本、改字写回（只在看得到的文字里找，认 HTML 实体）
- `lib/history.js` —— 设计版本：按内容存（没改的文件只存一份），最多 40 版，回到某一版
- `lib/serve.js` —— 预览服务器：静态文件 / 代理 / 改动推送 / 注入（picker 和一段收集页面报错、没载到的资源的小脚本）
- `lib/browser.js` —— 无头浏览器：找本机的 Chrome / Edge / Chromium / Brave，`--remote-debugging-pipe` 说话（不开端口），临时用户目录，闲置自己关
- `lib/look.js` —— `check_design` / `look_design` 的量和截：挑屏、解析尺寸、每种尺寸开一页量问题和测量数字、挑严重问题截局部图、截顶上 / 滚到底 / 整页分段 / 元素，整理成交给模型的字
- `lib/system.js` —— 品牌设计系统：在网页里收集颜色 / 字体 / 圆角 / 阴影 / 组件，扫项目文件夹，按 OKLab 聚类定角色（对比度够不够也算），写 tokens.css / components.css / 样张 / DESIGN.md，库（默认那套）和给技能补的一节
- `lib/tweaks.js` —— 调节滑块：读 tweaks.json、写回（:root 上的默认值、<html> 属性）、查有没有接上
- `lib/handoff.js` —— 转成代码：认现有项目、交接说明和截图、compare_design 的逐像素比（在无头浏览器里算差异、找成片的差异块、拼图）
- `lib/bundle.js` —— 远程看：把一屏的样式表（含 `@import`）、脚本、图片、字体内联成一份 HTML，放 `<base>` 和 picker
- `lib/phone.js` —— 手机上看：局域网入口（口令换 Cookie、转发到预览服务器、补 viewport、跟随跳屏、WebSocket 透传、闲置自动关）
- `lib/qr.js` —— 二维码生成（字节模式、纠错 M、版本 1–10，不引第三方库）
- `lib/picker.js` —— 页面里的脚本：选取、改动高亮（指纹比对）、生成动画、和右侧栏握手换帧（关闭的 shadow DOM，不污染页面样式）、把页面画成 PNG（样式、图片、字体都内联）、深色模式切换、报告屏间链接、演示时把点链接变成跳屏、就地改字、调样式（选中元素、实时套样式、认出用了哪些设计变量、每项由哪条规则决定）、远程看时接住跳页、给无头浏览器用的 `window.__dshDesign`（量、切深色、滚动、元素位置）
- `lib/client.js` —— 右侧栏、工具栏、画布（排版、拖动、缩放）、设备外框、动画、两帧 iframe 交替（新的载好再淡入）、设计规范面板、版本面板和左右对比、导出（套外框、合成展示图）、把选取整理成文字插进输入框、原型箭头和演示、多尺寸并排、改字、参考图取色、窄栏「更多」菜单、调样式面板、风格卡、远程看（打包的页面放进沙盒 iframe，跟着改动重新打包）
- `skills/ui-design/` —— 内置设计规范（DSH 技能）：`SKILL.md` 流程和原则、`references/` 各类型细则、`tokens.css` 起手模板
- `assets/hero.jpg`、`assets/demo.gif` —— 首页图和演示动图（全新 DSH 网页版装上插件、假模型按脚本出屏录的，设计稿是真模型做的）；`assets/showcase.jpg` —— 导出的展示图样例
- `docs/feasibility.zh.md` —— 做之前的可行性调研

## 已验证

新手走查（2026-11，DSH 0.2.1-rc.5）：按包名装、点「立即启用」不重启就能用；桌面端设计模式里真模型（DeepSeek-V4.1-Flash）从一句「帮我设计一个社区健身房的会员 App」做到六屏全套，再点选改一处。走下来修了五处：画布到 6 屏后预览不再刷新（每屏各开一条改动通知，占满了浏览器对同一地址的 6 条连接，现在由右侧栏转告）；电脑开着「总是显示滚动条」时 App 按 375 宽排版，右侧栏体检和模型的体检对不上；导出的图里外部 `icons.svg` 的图标是空的；整套展示图的大标题是文件夹名；点选进输入框后接着打的字粘在最后一行后面。另外加了几个方向并排时每屏都挂的「✓ 就要这个」和空白页的示例句子。

第一期之后又打磨了一轮，同样在全新的 DSH 0.2.1-rc.3 网页版里实测（`e2e/e2e-studio.mjs`，40 项全过）：模型用提问卡问话时，右侧栏提示「模型在等你回答」，答完提示消失；模型调 `check_design` 前后各一次，第二次只剩它改坏的那屏；「再出一版」写的 home-b 在画布上紧挨着首页；选中它点「就要这个」，输入框里是〔选定方向〕，让模型把原版挪进 `drafts/`。真模型（DeepSeek-V4.1-Flash）在桌面端设计模式里写完首页，自己调了两次 `check_design`（右侧栏量完把清单交回），改完再量一遍「0 个问题」，没有再另开浏览器截图；它写的 `_probe.html` 这类临时文件不再出现在画布上。新加的「文字被挤断行」拿真模型写的首页试，查出 5 处（「可外带」「再来一单」和三个价格）。

第一期（导出 PDF / PPT、设计体检）在一个全新的 DSH 0.2.1-rc.3 网页版里实测（`e2e/e2e-studio.mjs`，36 项全过）：打开设计后按钮上自动标出 4 个问题；模型调 `check_design` 拿回同样的清单（只列首屏，面板关着时再调只列购物车）；模型调 `preview_page` 开三屏 App，体检只在首屏查出埋的四个问题（文字截断、对比度 1.59:1、26×26 的按钮、8px 小字），另两屏零问题，预览里标上编号，点一条闪一下；「交给模型修」把清单放进输入框，发出去模型收到；改好首屏「再查一次」没问题；模型改完这一轮自动再量、按钮上的数字没了；面板开着时模型改坏购物车，面板自己刷新，被挡住的那屏挪出来；导出的 PDF 三页、PPT 三张竖版幻灯片，存进 `exports/`，不当成设计改动，里面「去点单」「加入购物车」能点着跳页，PDF 带每屏书签。PPT 也在 PowerPoint 里打开过，三张都正常、没有修复提示。桌面端重启后插件照常加载。真模型（DeepSeek-V4.1-Flash）在桌面端设计模式里说「帮我设计一个咖啡外带 App 的界面」：先用提问卡问了三个问题（感觉、场景、必须有的），答完写出 home-a / b / c 三个方向并排在画布上，最后再用提问卡问选哪个（也可以混搭）。这次发现两点已改：问完感觉后三个方向不该再跨风格；模型靠另开浏览器截图自查，一轮用掉一百多万 token——所以加了 `check_design`，并让三个方向在画布上按 a、b、c 排。
