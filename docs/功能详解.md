# 设计工作台：完整功能

仓库首页只放了重点，这里是全部功能、工具参数和安全设计。装法和三步上手见[首页](../README.md)。

## 用起来是什么样

1. **做设计时自动打开**：模型加载了设计技能、调了 `preview_page`，或页面写了设计类型标记（`<meta name="dsh-design">`）之后，再写 `.html` 文件或用命令起开发服务器（`npm run dev` 这类），右侧栏自动弹出「设计工作台」。别的任务写的网页不弹，只在标题栏按钮上亮个蓝点，点开能一键预览；`curl`、浏览器工具去看别的端口，一律不当成要预览的页面。
2. **分类型显示**：网页（浏览器窗口）、App（手机外框带灵动岛）、小程序（手机外框加微信右上角的胶囊，顶栏是深色时胶囊自动变白；顶栏是图片、渐变判断不准时，页面写 `<meta name="dsh-capsule" content="white">` 指定）、桌面软件（1280×800 的软件窗口，左上角 Mac 红绿灯；页面写 `<meta name="dsh-design" content="desktop windows">` 就画 Windows 右上角的三个按钮，顶栏是深色时按钮变白）、平板、海报（1080×1350）、幻灯片（16:9）、邮件。模型调工具时说明类型，或在页面里写 `<meta name="dsh-design" content="app">`（可带尺寸，如 `poster 1080x1920`）；工具栏「类型」菜单随时能换。
3. **多屏画布**：同一个目录里的几个 HTML 文件按生成顺序排成网格，能拖、能缩放（触控板双指滑 = 平移，捏合 / ⌘ 滚轮 = 缩放，右下角适合画布）。点一下选中一屏，双击只看这一屏；工具栏「画布 / 单页」切换。开发服务器可以让模型给几个路由并排看。
4. **看着它生成**：模型写一屏时，右侧直接显示它正在写出来的真页面——一段段往下长、自动跟着写到的地方滚（第一屏在等待卡片里，画布上在新那屏的格子里，单屏时就在手机里，写完自动换到这一屏）。三只带名字的鼠标（排版 / 配色 / 文案）只碰真正新长出来的东西，而且真的在干活：排版像设计软件那样把新的一大块拖出选框（四角有把手，尺寸边拖边跳，松手标上是什么）；配色那块新上色的先只留一圈虚线，配色点一下，颜色从点的地方刷满（字一直在上面，标签上带色号）；文案把新出来的一段字一个个打出来，打到哪露到哪。闲着的鼠标在正在写的地方候着，新东西淡入出来。模型停着它们也停着，不循环。样式还在写、正文还没开始时，先把定下来的颜色、字体一个个摆出来。还没开始写页面（在想、在看文件）时是按类型画的版面占位：鼠标先框一遍就停住，之后模型每换一件事、每多写一截才动一下。模型用提问卡问你时，状态条换成橙点「模型在等你回答」。
5. **实时刷新，不白屏**：本地 HTML 所在目录里任何文件一改，后台先载好新的一帧，再淡入换上来（滚动位置不丢）；开发服务器走它自己的热更新（Vite / Next 等的 WebSocket 照常通）。
6. **改了哪里一眼看到**：刷新 / 热更新前后各记一份页面「指纹」，改过、新加的元素在预览里亮一下（带一道扫光），都不在屏幕里就先滚过去；底下报「已更新 index.html · 1 处改动」。改的是共用的 CSS，画布上每一屏都会换帧、各自闪改动；只改某一屏的 HTML，别的屏不动。
7. **模型在干活时**：预览四周一圈流光，顶上一条状态条说它在做什么、用了多久：「在想… · 0:12」「正在做第 4 屏 · menu.html · 已写 120 行」「正在改「首页」」「正在体检」「正在跑命令」……（模型写大文件要好几分钟，文件名一到就说在写哪一屏、写了几行，不会一直「在想」；单屏看手机时设备往下让一点，不被状态条挡住）
8. **回首页**：开着设计时点左上角「首页」，首页叠在画布上（写了一半的话还在）；从这里说一句是另起一套，现在这套不动；「接着做」里标着「正在看」的那套点一下就回去，按 Esc 也回去。设计库在首页顶上的「市场 / 我的作品 / 灵感」。
9. **选择**：点工具栏「选择」，鼠标移到哪个元素就框哪个（带标签和尺寸，画布缩小时标签照样看得清；画布里点哪一屏都行）：
   - 点一下：选这个元素
   - 拖一块：选区域，里面的主要元素一起带上（最多 10 个）
   - Esc：取消
10. **进输入框**：DSH 0.2.1 起，输入框里放一个小标签，写「1 个元素」（框选区域写里面有几个元素），悬停看元素、选择器、大小和文件，接着打要怎么改就行；发出去的消息里也是这个标签。模型拿到的是整理好的整段文字（旧版 DSH 直接把这段插进输入框，插不进时复制到剪贴板，光标停在下面新的一行）。别的放进输入框的东西也一样是小标签，各有图标：标注图、改字、样式改动、再出两版、选定方向、体检清单、转成代码、参考图、滑块调整、设计系统、风格卡、设计变量；悬停看要点（标注图、参考图能看到小图），模型拿到的还是整段。选中的地方留一个虚线框。模型拿到的例如：

   ```
   〔选中元素〕a.btn-order「立即点单 →」
   文件：/Users/me/site/index.html
   位置：section.hero > div.actions > a.btn-order
   HTML：<a class="btn-order" href="#menu">立即点单 →</a>
   样式：165×56 · color: rgb(255, 255, 255) · padding: 16px 36px · border-radius: 999px
   ```

   React / Vue / Svelte 的开发模式下还会带上组件名和源码位置。
11. **内置设计规范**：插件带一个 DSH 技能 `ui-design`，模型做界面前会加载：先定类型和画幅、先写 `tokens.css`（设计变量）、一屏一个文件；排版 / 间距 / 字号阶梯 / 配色 / 对比度 / 中文排版的规则，避开「AI 味」的清单，写完的自查表；网页、App、海报、幻灯片、邮件各有细则。从零做一套新设计时，模型先问两三个关键问题（给谁用、什么气质、要哪几屏），再出三个方向的首屏（`home-a/b/c.html`，各带一套配色字体）并排摆在画布上，你挑一个它再做全套，没选中的挪进 `drafts/`（问的时候已经挑了气质，三个方向就都在这个气质里，换版式和重点）；说「直接做」、或者需求已经很具体，就跳过这一步。在输入框打 `/ui-design` 也能手动加载。
12. **设计规范面板**：工具栏调色板按钮，列出这套设计 `:root` 上的设计变量，按颜色、字体、字号、间距、圆角、阴影分组，带色块和样例。点一个放进输入框（`〔设计变量〕--brand: #c26a32` 加文件位置），补一句「换成墨绿」，模型改这一个变量，所有屏一起变。还没有变量时，一键让模型按规范建一份。
13. **导出**：工具栏下载按钮，或画布上选中一屏后标签旁的按钮。可以导出这一屏（带手机 / 浏览器外框，或纯画面）、整页长图，以及几屏合成的一张展示图（品牌名做大标题、背景和主色取自设计变量，适合直接发朋友圈 / 小红书 / 作品集）。也能把所有屏导成 **PDF**（每屏一页，网页 / 邮件是整页长图，页面尺寸跟着画幅）或 **PPT**（每屏一张幻灯片，整页图片，幻灯片比例跟着画幅，PowerPoint / WPS / Keynote 都能打开）。屏和屏之间的跳转照样能点：PDF 里点「去点单」翻到菜单那页（每屏还有一条书签），PPT 放映时点了跳到那一张，导出的文件就是能点的原型。文件存到设计目录的 `exports/`，图片同时复制到剪贴板，点「打开文件夹」直接定位。
14. **版本**：每轮对话开始前、结束后各自动存一版（只存设计文件，名字就是你那句话，例如「主色换成深海蓝」；点选元素发出去的，名字是「「3.2 km」 · 改成绿色」这样，不会是一长串选择器）。工具栏时钟按钮列出所有版本；点一版就看当时的样子（画布 / 单页都行），点「对比」左右拖动把手，比较那一版和现在；「回到这一版」把文件写回去（回之前先把现在的存一版，随时能再切回来）。
15. **深色模式**：页面写了深色样式（`@media (prefers-color-scheme: dark)`，或 `[data-theme="dark"]` / `.dark`），工具栏多一个月亮按钮，一键切换看深色版，导出的图片也是深色的。
16. **再出两版**：画布上选中一屏，点标签旁的闪光按钮，让模型给这一屏出两版不同方向的设计（`login-b.html`、`login-c.html`），紧挨着原版排在画布上（开局的三个方向 `home-a/b/c` 也一样，按 a、b、c 排）。挑中哪版就点它标题旁的「✓ 就要这个」（几个版本并排时每屏都挂着，不用先选中）：输入框里写好「用这一版、其他版本挪进 `drafts/`、接着做全套」，发出去就行。
17. **在手机上看**：工具栏扫码按钮，右侧栏出一个二维码，手机（和电脑连同一个 Wi-Fi）相机一扫就在手机浏览器里打开这套设计，按真机尺寸看、点得动。电脑上点哪一屏，手机跟着跳；模型改了设计，手机自动刷新。面板上看得到「手机已打开」，也能复制链接、随时停止；30 分钟没人看自动关。
18. **可点原型**：屏和屏之间用链接连起来（`<a href="detail.html">` 或 `data-href`，内置技能会让模型这么写），画布上选中一屏，就画出它能跳去哪：从按钮出发、沿屏和屏之间的空当横平竖直走、转角带圆角，几条线各走各的道、尽量不交叉，不穿过别的屏；底栏、返回这种每屏都有的导航只描虚线框，不画线。点底部工具坞的「试用」进入试用：在预览里点按钮跳到对应那一屏，前进从右边滑进来、返回从左边；顶上能后退、从头来、退出（Esc）。
19. **多尺寸并排**：工具栏第三个视图按钮，把现在这一屏按几档宽度并排看：网页是手机 / 平板 / 桌面，App 是小屏 / 标准 / 大屏（小屏是 SE 那种矮屏，没有灵动岛），平板是三种尺寸，小屏挤不挤一眼看出来。并排时也能选择元素，带上是哪一档屏宽。
20. **预览里直接改字**：工具栏「改字」按钮，点页面里的任意文字就地改，回车保存、Esc 取消。本地 HTML 直接写回源文件（只改那一处，改前改后各存一版，能回退）；开发服务器的页面，或源码里找不到那段字时，改成一句「把「…」改成「…」」放进输入框，交给模型改。
21. **参考图**：把图片拖进右侧栏、在右侧栏里粘贴，或在设计规范面板点「照参考图改风格…」。图片存进设计目录的 `refs/`（还没有设计目录时存插件缓存），右侧栏从图里取出主要颜色（带占比，少见的鲜艳点缀色也会单独挑出来）和整体深浅，连同图片路径和一句「照这张图的风格改，先更新 tokens.css」放进输入框。
22. **设计体检**：工具栏听诊器按钮，在画好的页面上实测：文字超出屏幕、被截断、超出框、叠在一起，文字和背景对比度不够（按 WCAG，大字 3:1、正文 4.5:1），点击区太小（App 44、网页 24），字太小，图片没加载出来或被拉变形，一行太长（网页 / 邮件 / 平板，中文超过约 45 字、英文约 90 个字母），按钮、价格这种短字被挤得断了行（「再来一 / 单」），字号太杂，小程序页面的字或按钮伸进了右上角胶囊，手机页面的字或按钮伸进灵动岛或底部横条区，底部标签栏超过 5 项，小程序没画顶部导航栏，桌面软件的字或按钮压在窗口按钮上。画布上每一屏都查，问题按屏列出来，预览里在对应位置标上编号（严重的标红）；点一条就滚过去闪一下。点「交给模型修」，清单（哪一屏、哪个元素、什么问题、差多少）放进输入框，发出去模型逐条改源文件。模型每干完一轮，右侧会自己量一遍：面板开着就直接刷新，关着就在按钮上标出还剩几个问题（没有数字就是都好了）。点一条时，那一屏要是被面板挡着或在画布外面，画布自己挪过来。模型自己也能体检：设计模式里它写完、改完会调 `check_design`——插件在电脑上另开一个看不见的 Chrome / Edge，按真实尺寸打开每一屏量一遍（一次可以量几种尺寸，比如 375×667 的矮屏和 430×932 的大屏，也能量深色），清单里还有每屏的测量数字：页面多高、顶栏 / 底栏多高、离内容多远。这条路另外查四类问题：固定的顶栏 / 底栏压住了内容或贴得太近（滚到底最后一行被底栏挡住这种；滚动中从栏下面经过不算）、页面脚本报错、样式表 / 脚本 / 字体没载到、跳转指向不存在的页面。对比度不够、字太小这两类还写明由哪条样式规则决定、在哪个文件第几行；严重的问题（被栏压住、文字叠在一起 / 被截断 / 超出框、超出屏幕、图片没出来、对比度很低）自动附上那一块的局部截图（最多 4 张，按发现时的尺寸和滚动位置截；红框圈出元素、框上标差多少，叠着的另一个用橙框；被栏压住的把栏调成半透明，透出下面的字；挨着的几条共用一张），模型不用再单独截图对照。文字叠在一起时还找出可能的原因（负 margin、绝对定位、transform），写明那条规则在哪个文件第几行；同一个原因引起的几处并成一条。再量一次时写「比上次修好几个、新出几个」，新出的标出来；有没量成的就明说检查不完整。不用右侧栏开着；电脑上没有 Chrome / Edge 时退回右侧栏量。
23. **调样式**：工具栏滑块按钮，点页面里的一个元素，右边出属性面板：字号、字重、文字颜色、背景、圆角、上下 / 左右内边距（排成一行 / 一列的容器还有间距）。拖滑块页面上马上变；颜色旁边列着这套设计的色块，元素原来用的是设计变量（如 `--brand`）会标出来。「写回文件」把改动写进 HTML 里这个元素的 `style` 属性（改前改后各存一版，能回退）；「交给模型」把「字号 16px → 18px」这样的清单放进输入框，让模型写进样式表、能用设计变量就用设计变量；还附上每项现在由哪条样式规则决定、在哪个文件第几行（行内 style 盖过了规则也说清楚），模型不用再翻源码找。没写回就退出，页面恢复原样。开发服务器的页面只能交给模型。
24. **风格卡**：二十套现成风格——极简白、温暖手作、杂志编辑、深色高级、活泼年轻、清新自然、专业科技、玻璃质感、柔和立体、国潮、中式雅致、赛博朋克、可爱卡通、复古、电商促销、日系原木、瑞士网格、粗野主义、奶油风、运动能量。每张卡是用这个风格画好的一小屏界面（顶栏、标题、按钮、商品卡、数据卡）；点一张看原大样板，左右键翻着比，满意了点「用这个风格」。还没开始设计时，在首页输入框的「风格」里挑，发出去时带上〔风格〕和整套配色；已经有设计了，在设计规范面板点「换个风格…」，模型先改 `tokens.css`，再把写死的颜色换掉，版式和文字不动，改完自己体检一遍。
25. **远程也能看**：从手机（dsh-mobile 走外网）或别的电脑打开 DSH 网页时，电脑本机的预览端口那边连不上。本地 HTML 做的设计，插件把一屏连同样式、脚本、图片打成一份传过去，放进沙盒 iframe 显示，选择、改字、调样式、体检、导出照样能用；页面里点跳转就换到那一屏，文件改了跟着刷新（只刷用到这个文件的屏）。开发服务器的页面打包不了，还是只给一句说明。
26. **模型自己看图**：模型想看真实渲染的样子时调 `look_design`：同样用那个看不见的浏览器，按指定尺寸截一屏——顶上一屏、滚到底、整页分几段，或者只截某个元素（比如底栏），也能截深色——图直接交给模型看。不用自己起服务器、写截图脚本。
27. **品牌设计系统**：给一个网站地址或项目文件夹（「照我们官网的风格」），模型调 `extract_design_system`，插件用看不见的浏览器打开网页量真实渲染的样式——底色、正文和次要文字、主色、点睛色、边框，字体和字号阶梯，圆角、阴影，主按钮 / 次按钮 / 输入框 / 卡片 / 顶栏的样子——项目文件夹还会扫 CSS 变量、写死的颜色、Tailwind 配置和组件库。提出来的是一整套文件：`tokens.css`（和技能起手模板同一套变量名）、`components.css`（按钮、输入框、卡片、文字样式）、`components.html` 样张、`DESIGN.md` 说明，连同网站和组件截图存进 `~/.dsh/design-systems/<品牌>/`。设成默认后，以后每次做新设计模型都先复制这一套，不再问「想要什么感觉」，三个方向只在版式上拉开。右侧栏设计规范面板里「品牌设计系统…」（窄的时候在「更多」里）列出所有套，带样张缩略图和色块，能设默认、取消默认、一键套用到当前设计，也能直接填地址让模型提一套。
28. **调节滑块**：模型给这套设计挑几个最值得试的维度（留白疏密、圆角、主色、卡片排法……）写进 `tweaks.json`，工具栏旋钮按钮列成滑块、取色、几选一；拖的时候画布上每一屏一起变（只改页面上的 CSS 变量和 `<html>` 上的属性，不动文件），满意了「写回文件」（变量写进 `tokens.css` 的默认值，属性写到每屏的 `<html>` 上，改前改后各存一版），或「交给模型」照这几个值改、顺手协调相关的地方。还没有滑块时一键让模型做几个；`check_design` 会顺带查滑块有没有真接上（变量没人用、没有默认值、选项没有对应的样式）。
29. **转成代码**：工具栏 `</>` 按钮，选用什么做（跟现有项目一样 / React / Vue / Next.js / 纯 HTML；小程序的设计多两个：uni-app、微信原生小程序，默认 uni-app）、代码放哪、转全部还是这一屏，点「开始转成代码」。模型先调 `handoff_design`：插件在设计目录写一份 `handoff/HANDOFF.md`（每屏的文件、建议路由、跳去哪，设计变量，几屏共用该抽成组件的部分，脚本 / 表单 / 悬停这些交互，滑块，图片字体，做法和验收）和每屏从上到下的截图；模型照着一屏一屏写，每屏写完把开发服务器跑起来调 `compare_design`：同样尺寸各截一张逐像素比，回一张「设计稿 | 做出来的 | 差异」拼图，差得多的地方红框标号、写明两边分别是哪个元素，差异降到 3% 以下再做下一屏。「跟现有项目一样」也认得出 uni-app（命令行建的，和 HBuilderX 建的、没有 package.json 的）、Taro、微信原生小程序（project.config.json + app.json）。做成小程序时交接说明换成小程序的写法：页面登记进 pages.json / app.json、`view` / `text` / `image` 换掉 HTML 标签、px 换 rpx、设计变量写在 `page` 上、图标拆成单个文件用 `<image>`、主包 2MB；uni-app 跑网页版（`npm run dev:h5`，HBuilderX 里「运行到浏览器」）照样逐像素比，原生小程序在浏览器里跑不起来，改成让你在微信开发者工具里看。
30. **画笔标注**：工具栏画笔按钮，预览上盖一层画布，直接在页面上画：画笔、荧光笔、箭头、方框、圆圈、文字、橡皮（点到哪一笔擦哪一笔），八种颜色、三档粗细，能撤销 / 重做（⌘Z / ⇧⌘Z）、一键清掉；按住 Shift 画正方形、正圆，箭头吸到 45°。头三次打开时页面中间有三步说明（画了就收起），底栏一直写着现在这支笔怎么用（「圆圈 · 按住拖一下，圈出要改的地方」）。圈、框、箭头和字都是手绘风（字是楷体，下面带一道手画的线），像拿笔在打印稿上圈。单页、画布都能画，画的时候预览不动。点「交给模型」：台面上看得到的几屏各截一张、按位置摆好，叠上画的东西，裁成一张图存进设计目录的 `refs/`（`markup-首屏名.png`）；输入框里放一个「标注图」标签（悬停看图和图上写的字），模型拿到〔标注〕、图的路径、「先用 read_image 看图，按圈、箭头和文字改」和图上写的字，再补一句要怎么改就能发。点「复制」（⌘C）：拼成同一张图放进剪贴板，贴到别的工具、聊天软件里用（http 远程打开时没有这个按钮，浏览器不让写剪贴板）。Esc 或「取消」退出，画的不留。

31. **打开已有的 HTML**：首页输入框左边的「+」→「打开已有的 HTML…」选一个本地 HTML 文件（网页版会展开最底下的地址框），或把 HTML 文件 / 文件夹拖进右侧栏，直接打开预览（桌面版；网页版拿不到本地路径，照旧输路径）。打开地址栏时旁边也有选文件的按钮。文件夹里有 `index.html` 开它，没有就开最先做的那屏，同目录的几屏照样排在画布上。品牌设计系统的来源、转成代码的「代码放在」旁边也有选文件夹按钮；「代码放在」选的是项目（有 package.json、`.git`，或者有 index.html 的纯 HTML 站点，后者框架会自动选「纯 HTML」）、项目里的子目录（比如 `src/pages`，框架跟那个项目）或空文件夹就放进去，选了别的有东西的文件夹（比如 `~/Projects`）就在里面新建 `<设计名>-app`；选到设计目录里面就改放旁边，选完下面会说一声。项目没认出前端框架（后端、monorepo 根目录、别的语言的仓库）时，交接说明会让模型先看清结构，再决定页面放哪个子目录，不在原地跑脚手架。预览页面自己有上传区的，拖到上传区上照样交给页面自己收。
32. **设计库**：「更多」→「设计库」（或输入框里打 `/design-library`），分三页：
    - **市场**：大家分享的模板（网页、App、小程序、海报……）、设计系统和风格卡，能搜、按类型和风格筛。点开看每屏大图；App、小程序、平板、邮件、网页还能「实时看」，在下面说的硬规矩里真跑一遍。「用这个开始」把整套复制进当前会话的文件夹，画布上直接打开，接着让模型改；复制走的就是你的，市场以后下架也不受影响，CC BY 的会带一份 `ATTRIBUTION.md` 署名。设计系统点「装进设计系统」进品牌设计系统列表；风格卡点「+」收进灵感。☆ 收藏一套，以后在灵感里找。市场的目录缓存在本机，断网也能看上次的。
    - **我的作品**：以前在各个会话里做过的设计都记在这里，能置顶、打开、在文件夹里显示、打成 zip、分享到市场、移出列表；文件夹挪了能重新定位。从市场来的原模板被下架了，卡片上标一行（你这份照常能用）。
    - **灵感**：收的参考图、网址、风格卡，和收藏的市场设计（被下架的标出来）。
    别人发来的设计 zip 拖进右侧栏，也能「用这个开始」。
33. **分享到设计市场**：「我的作品」卡片上的分享按钮，或导出菜单里的「分享到设计市场」。填名字、一句话介绍，选授权（CC0：随便用；CC BY：要署你的名），勾四个确认（自己做的、品牌是虚构的、没有真实个人信息、同意公开），点「检查并打包」。插件先按市场规则查一遍（真实个人信息直接拦），再用那个看不见的浏览器断网打开每屏体检：机器人会拒的问题（被系统栏压住、图片坏了、跳到不存在的页）先在这拦下，可以一键「让模型帮我改好」。过了就在「下载」里生成 zip；点「打开投稿页」（标题、授权、短名已经填好），把 zip 拖进去提交，几分钟后机器人在那条 issue 里回复结果，审过就上架。「我的作品」里这套先显示「分享过 · 还没上架 · 看投稿进度」，上架后变成「已上架 · 去市场看」。投稿要有 GitHub 账号。

工具栏还有：地址（点一下能改，输文件路径 / 端口 / localhost 地址都行）、刷新、在浏览器里打开。右侧栏拉窄时，不常用的几个按钮收进「更多」菜单。会话标题栏右边有个「设计工作台」按钮，随时打开。DSH 重启后，每个会话接着预览原来的页面（类型、视图也记着）。

`preview_page` 工具的参数：`target`（文件路径 / 端口 / 地址）、`kind`（web / app / miniprogram / tablet / poster / slides / email）、`size`（如 `1080x1920`，可选）、`screens`（开发服务器上并排看的几个路由，可选）。`check_design`：`screens`（只量哪几屏）、`sizes`（如 `["375x667","430x932"]`）、`dark`、`images`（`false` 不附截图）。`look_design`：`screens`、`size`、`at`（top / bottom / full）、`selector`（只截这个元素）、`dark`。`extract_design_system`：`sources`（网址 / 项目文件夹 / HTML 文件，1–5 个）、`name`、`default`。`handoff_design`：`framework`（same / react / vue / next / html / uniapp / weapp）、`dest`、`screens`。`compare_design`：`url`（做出来的页面，本机地址或端口）、`screen`、`size`、`at`（top / bottom）、`dark`。

## 设计模式和开关

新会话的模式菜单里多了一个「设计模式」：标准模式的全部工具，加上设计技能和右侧工作台的预览，人设换成做设计的。做界面时选它；标准、创造等模式照常能用这些功能。

插件拆成几个组件，DSH「插件」→「设计工作台」里每个都能单独开关，马上生效，不用重启：

| 组件 | 管什么 | 默认 |
| --- | --- | --- |
| 设计工作台 | 右侧栏和预览服务器（关掉就等于不用这个插件） | 开 |
| 自动打开预览 | 做设计时写了 HTML、起了开发服务器，右侧自动打开；关掉后只在右侧栏给一个「预览刚写的 …」按钮 | 开 |
| 预览和体检工具（其他模式） | 标准、创造等模式也能用 `preview_page`、`check_design`、`look_design`、`extract_design_system`、`handoff_design` 和 `compare_design` | 开 |
| 设计技能（其他模式） | 标准、创造等模式也能加载 `ui-design` 技能 | 开 |
| 设计模式 | 模式菜单里的「设计模式」 | 开 |
| 设计库不联网 | 打开后设计库一个网址都不访问：不取市场目录、不下载设计；缓存里已有的目录照常能看 | 关 |

只想在设计模式里做设计、别的模式保持干净：关掉两个「（其他模式）」。设计模式自带工具和技能，不受这两个开关影响。

## 能预览什么

| 输入 | 怎么预览 |
| --- | --- |
| 本地 HTML 文件 / 目录 / `file://` | 插件起一个本机服务器给这个目录，目录里的文件一改就刷新（目录：有 `index.html` 开它，没有就开最先做的那屏） |
| 端口、`localhost:端口`、`127.0.0.1:端口` | 插件起一个代理转给开发服务器，热更新照常（只听 IPv6 `::1` 的也行，比如 Mac 上的新版 Vite） |
| 外网地址 | 不支持（只预览本机页面） |

## 安全

每个预览目标一个独立的 `127.0.0.1` 随机端口，和 DSH 不同源，页面里的脚本碰不到 DSH。

- **只给这个目录**：路径按真实位置算，`../`、编码过的 `../`、指到目录外的软链接都拒。
- **防 DNS 重绑定**：Host 必须是本机名加这个端口。
- **和右侧栏通信**：只和 DSH 自己的源说话（桌面版 `dsh-app://app`、DSH 网页端的地址）：发消息指定收件的源，收消息要来自父窗口且源对得上。别的网站把预览嵌进去，收不到也指挥不动。用反向代理或域名打开网页版 DSH 时，这个地址得写在 DSH 的 `trustedHosts`（`dsh-client-connection` 配置）里才认；没写的话点选、改字、导出不起作用。
- **接口**（`/dsh-design-studio/api/*`）：交给 DSH 自己的 `connection` 服务验登录态；老版本 DSH 没有这个服务时只收本机、同源请求。
- **手机上看**：默认不开，点了才在局域网开一个入口；只监听本机在局域网里的那个地址（不是 0.0.0.0），Host 也得对。链接带一次性的随机口令（128 位），手机第一次打开换成只给这个端口的 Cookie（HttpOnly），地址栏里不留口令；没口令、口令不对一律 403。停止或 30 分钟没人看就关端口，再开换新口令。同一个 Wi-Fi 里拿到这个链接的人也能看，所以别把链接发到群里。
- 代理开发服务器时会拆掉 `X-Frame-Options` 和 CSP（不然嵌不进右侧栏），只影响预览端口，开发服务器本身不动。
- **远程看**：打包好的页面放在 `sandbox="allow-scripts allow-forms"` 的 iframe 里（不透明的源，碰不到 DSH 的 Cookie 和接口），页面里放一个 `<base>` 指着原来的预览地址，拿不到 DSH 网页的地址；只内联设计目录里的文件（越界、软链接到外面的不读），总量 12 MB 封顶；接口回 JSON，不在 DSH 的地址下直接给 HTML。
- **设计市场**：目录是一个签了名的 npm 包（`dsh-design-gallery`），插件里钉死了公钥（ed25519）：签名不对、编号比上次见过的小（想退回旧目录）都不用。设计内容在另一个包（`dsh-design-gallery-packs`）里，每个文件都按目录里的 sha256 核对，大小有上限，解压防越界。只访问 npmmirror、腾讯云、华为云的 npm 镜像和 registry.npmjs.org（几个一起试，谁先回用谁），跳转也只跟这几个；下架名单记在本机，目录漏发也不会放出来。在「插件」里打开「设计库不联网」就一个都不访问。
- **别人做的设计**（市场来的、拖进来的 zip，且没改过）：预览时加硬规矩——只有插件自己的两段脚本能跑，不联网（样式、图片、字体只能来自本机预览地址），表单交不出去，不能嵌别的页面；第一版市场本来也不收脚本和字体文件。你改过以后，就当你自己的设计照常预览。
- **分享**：包里不带你本机的路径和来源记录，图片去掉拍摄信息（EXIF、GPS）。「分享记号」只存在你自己的 `design.json` 里，包和目录里只有它的哈希（用来认出「已上架」），不含任何个人信息。
- **调样式写回**：只收字号、颜色、圆角这几个属性，值里不许有 `url(`、引号、分号这类东西；按标签、序号、id、class 在源码里认出那个元素，认不准就不写，改成交给模型。
